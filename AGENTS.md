# Правила работы с проектом

- Архитектура: модульный монолит с упрощёнными портами и адаптерами.
  Домен не зависит от HTTP, PostgreSQL или телеметрии.
- Логирование через zap; сохранять корреляцию trace_id/span_id/request_id.
- После изменений Go обязательно применить `golangci-lint fmt` и выполнить
  `golangci-lint run ./...`. Исправить найденные проблемы до завершения задачи.
- После изменений JavaScript, HTML или CSS обязательно выполнить
  `npm run format` и `npm run format:check` (Prettier).
- Не ослаблять конфиги линтеров ради прохождения проверок. После последних
  исправлений повторить затронутые проверки.
- Автоматические тесты временно отложены по решению пользователя. Не добавлять
  тесты, тестовые базы и шаги запуска тестов в CI без нового поручения.
- В итоговом ответе указывать только фактически выполненные проверки.
  Если проверка заблокирована окружением, явно сообщить об этом.
- Персональный скилл с этими правилами: `go-js-quality`.
- Коммиты и push оставлять пользователю, пока он явно не поручит их выполнить.
