## Что было сделано

Приложение для управления платёжными счетами запущено в minikube — локальном
Kubernetes с одной нодой. Docker запущен через Colima.

По Dockerfile собран образ `sre-payments:minikube` и загружен в minikube.
Один образ используется для API с веб-интерфейсом, фонового обработчика (worker)
и миграций — подготовки таблиц в базе данных.

Сначала запущен PostgreSQL, затем выполнены миграции, после них — API и worker.
При проверке число экземпляров API увеличено с одного до трёх, worker — с одного
до двух. Через веб-интерфейс создан, выставлен и отменён учебный счёт.

## Какие абстракции Kubernetes использованы

| Абстракция | Для чего используется в приложении |
| --- | --- |
| **Namespace** | Объединяет ресурсы приложения в пространстве `sre-payments`. |
| **ConfigMap** | Передаёт настройки: порт API, уровень логирования и интервал работы worker. |
| **Secret** | Передаёт имя пользователя, пароль и строку подключения к PostgreSQL. Используются учебные данные доступа. |
| **Deployment** | Поддерживает нужное число экземпляров API и worker, позволяет их масштабировать. |
| **ReplicaSet** | Создаётся Deployment и поддерживает заданное число подов. |
| **Pod** | Запускает контейнер с API, worker, PostgreSQL или миграциями. |
| **StatefulSet** | Управляет одним экземпляром PostgreSQL со стабильным именем пода и постоянным хранилищем. |
| **Service** | Даёт постоянные сетевые адреса: `payments-api:8080` для API и `postgres:5432` для базы. |
| **Job** | Выполняет миграции базы и завершается после успешного выполнения. |
| **PVC и PV** | PVC запрашивает 1 GiB хранилища, minikube создаёт PV. Данные базы сохраняются при пересоздании её пода. |

Для API используется Service типа ClusterIP, для PostgreSQL — headless Service,
который позволяет находить под базы по DNS-имени. Отдельный Service для worker
не требуется: он сам обращается к базе и не принимает запросы от API.

## Как сервисы взаимодействуют между собой

Пользователь открывает веб-интерфейс в браузере. Интерфейс встроен в API
и отправляет ему HTTP-запросы для создания, просмотра и изменения счетов.
API выполняет эти действия и сохраняет данные в PostgreSQL.

Worker каждые 5 секунд обращается к той же базе, находит счета с истёкшим сроком
оплаты и меняет их статус. API и worker напрямую друг друга не вызывают:
их общие данные находятся в PostgreSQL. Все экземпляры API и worker используют
одну базу данных.

Job миграций также подключается к PostgreSQL. Он подготавливает таблицы до
запуска API и worker. Параметры подключения компоненты получают из Secret,
остальные настройки — из ConfigMap.

Для открытия приложения на компьютере используется локальный туннель:
порт 18080 направляется в API на порт 8080. База данных остаётся внутри кластера.

## Файлы в архиве

- `Dockerfile` и `.dockerignore` — файлы для сборки образа из корня исходного проекта.
- `deploy/minikube/namespace.yaml` — пространство имён.
- `deploy/minikube/config.yaml` — настройки приложения и данные подключения к базе.
- `deploy/minikube/postgres.yaml` — PostgreSQL, его Service и запрос хранилища.
- `deploy/minikube/migrate.yaml` — задание миграций.
- `deploy/minikube/api.yaml` — API и его Service.
- `deploy/minikube/worker.yaml` — фоновый обработчик.
- `deploy/practice/pod.yaml` — временный под, использованный для тренировки работы с Kubernetes.
- `Отчёт.md` — этот отчёт.

Архив содержит файлы сборки и развёртывания; исходный код приложения берётся
из проекта. Скрипты и вывод команд в архив не включены.
